## Stack tervalidasi Context7 (2026-08-29)

- **Hono** template `cloudflare-workers+vite` (`bun create hono@latest`) + `jsxRenderer`; static assets via `"assets": {"directory": "public"}`
- **Better Auth**: `database: env.DB` (binding D1 langsung, auto-detect, atomicity via `batch()`); `socialProviders.google` + `baseURL` wajib (hindari redirect_uri_mismatch; daftarkan `http://localhost:3000/api/auth/callback/google` + URI produksi di Google Cloud Console)
- **Drizzle ORM + drizzle-kit**: `dialect: 'sqlite'`, `driver: 'd1-http'`, `migrations_dir` di `wrangler.jsonc`, `wrangler types`, `compatibility_flags: ["nodejs_compat"]`
- **D1** (5 GB, 5M rows read/100K write per hari), **R2** (10 GB, no egress), **Workers Free** (100K req/hari, 10ms CPU) — dicek vs docs resmi Aug 2026
- **HTMX + Tailwind v4 + Zod**; deploy **GitHub Actions** (`cloudflare/wrangler-action`, `oven-sh/setup-bun`)

## Skema D1 final (locked 2026-08-29)

**Milik Better Auth:** `user` (ditambah kolom `role TEXT DEFAULT 'siswa'`, `no_wa TEXT`), `session`, `account`, `verification`.

**Tabel aplikasi (4 tabel + 1 enrollment + 1 sync function):**

```
-- Tabel inti rombel
class_groups          (id PK, name, tahun_ajaran)
class_group_members   (group_id FK, user_id FK)              PK(group_id,user_id)
class_group_courses   (group_id FK, course_id FK)            PK(group_id,course_id)

-- Satu-satunya tabel enrollment (semua sumber bermuara ke sini)
enrollments           (course_id FK, user_id FK, source['rombel'|'manual'],
                       enrolled_by, enrolled_at)              PK(course_id,user_id)

-- Course & materi
courses               (id PK, title, slug, description, cover_key→R2, join_code, status, created_by)
lessons               (id PK, course_id FK, title, position, status)
lesson_blocks         (id PK, lesson_id FK, type['markdown'|'embed'|'file'|'callout'],
                       provider['tally'|'google_form'|'youtube'|'r2_pdf'|null],
                       url, meta JSON, position)

-- Progress & kuis
progress              (user_id, lesson_id, status['viewed'|'done'], marked_by, updated_at)
quizzes               (id PK, lesson_id FK, title, time_limit_s, pass_score, published)
quiz_questions        (id PK, quiz_id FK, prompt, options JSON, correct_keys JSON, points, position)
quiz_attempts         (id PK, quiz_id FK, user_id FK, started_at, submitted_at, score, passed, answers JSON)

-- Tally webhook (v1.1)
```

**Fungsi sync (dipanggil 3 trigger):** tambah/keluarkan anggota rombel, tambah course ke rombel → `INSERT OR IGNORE` enrollment source='rombel' + hapus enrollment rombel yang tidak relevan lagi. Enrollment manual → insert source='manual'.

**Yang TIDAK dibuat:** tabel `enrol` terpisah (Moodle-style plugin table), course meta link table, paket enrollment. Semua bermuara ke `enrollments`.

## Aturan embed (v1)

- Whitelist host di server saat save `lesson_blocks.url`: `tally.so`, `*.tally.so`, `docs.google.com`, `youtube.com`, `youtube-nocookie.com`, domain sendiri. Di luar itu → tolak + pesan error jelas.
- CSP halaman lesson: `frame-src 'self' https://tally.so https://docs.google.com https://www.youtube.com;` iframe pakai `sandbox="allow-scripts allow-same-origin allow-forms allow-popups"`, `loading="lazy"`.
- Normalisasi URL provider → URL embed resmi (YouTube `watch?v=` → `embed/`; GForm `/edit` → `/viewform?embedded=true`; Tally `/form/` → `/embed/`).
- File materi: upload → R2, serve via route `/files/:key` yang cek sesi + enrollment (jangan public bucket URL).
- Progress v1: tombol "Tandai selesai" (siswa) + centang manual guru. Selesai-kuis → otomatis `done` lewat tabel internal.

## Webhook Tally (v1.1 — desain sudah final, tinggal eksekusi)

1. Endpoint `POST /hooks/tally` ( publik, tanpa sesi): baca body **mentah**, verifikasi `tally-signature` = HMAC-SHA256-base64 dengan secret `TALLY_WEBHOOK_SECRET`, gagal → 401.
2. `INSERT OR IGNORE` raw ke `tally_submissions` (idempoten terhadap retry Tally), balas 200 < 1 detik.
3. `ctx.waitUntil(processSubmission)`: mapping key→kanonik via `tally_field_map` → tulis tabel tujuan (pendaftaran siswa → `user` status pending) → field tak dikenal → tandai `needs_review` + WA alert admin.
4. Field `FILE`/`SIGNATURE`: unduh dari URL Tally (accessToken+signature, bisa kedaluwarsa) → simpan ulang ke R2 segera.
5. Hidden field `user_id` (via URL embed) → sambungkan submission ke akun.
- Catatan format signature versi baru `t0=ts,v1=hmac` → pakai lib `standardwebhooks` atau parsing dua format.

## Model notifikasi WA (disederhanakan — user: "pada dasarnya ini untuk notifikasi")

Prinsip: **outbound saja, one-way, tanpa inbox.** Siswa tidak membalas; tidak perlu webhook incoming, tidak perlu `wa_inbox`. Ini memangkas separuh kompleksitas M7.

Tiga kanal, dipakai bertingkat (murah → mahal):
| Kanal | Biaya | Untuk apa |
|---|---|---|
| **Broadcast manual di grup WA kelas** | Gratis | Pengumuman rutin yang tidak perlu personal (jadwal, info umum) — v1, tanpa kode |
| **API WA trigger personal** (kirim.dev) | Gateway ~puluhan rb/bl + Meta ~Rp 350–450/penerima (utility) | Hanya yang butuh personalisasi: "Kamu belum menyelesaikan modul X", hasil kuis, pengumuman khusus kelas |
| **Notifikasi in-app** (lonceng/badge di LMS) | Gratis | Pelengkap default; WA hanya untuk yang urgent |

Kandidat trigger API (pilih paling penting, max 1–2 untuk awal):
1. Reminder mingguan siswa aktif yang progress-nya mandek (cron Worker → query `progress` → kirim template) — dampak terbesar.
2. Pengumuman modul baru ke enrolled students.
3. Hasil kuis (nilai keluar) — nice-to-have.

Aturan hemat: satu template per orang per minggu (cap), gabungan banyak pesan jadi satu, jangan pakai kategori marketing (mahal ~Rp 750–850). Estimasi kasar: 200 siswa × 4 kirim/bl × Rp 400 ≈ Rp 320rb/bl; dengan cap 2/bl ≈ Rp 160rb/bl + langganan gateway.
⚠️ Perubahan Meta (1 Okt 2026): pesan utility dalam service window yang tadinya gratis mulai dikenakan biaya — jangan berasumsi "gratis" saat M7 tiba; cek tarif terkini.
Catatan vendor: kirim.dev vs kirimdev.com adalah produk berbeda (kemiripan nama); pastikan yang dimaksud user saat M0, bandingkan harga.

**Rekomendasi urutan:** luncurkan LMS tanpa API WA (grup broadcast manual + in-app). Aktifkan API di M7 hanya setelah terasa kebutuhan nyata kirim personal — keputusan biaya tertunda sampai data pemakaian riil ada.

**KEPUTUSAN FINAL (2026-08-29): TANPA API WA. Hanya wa.me link bergenerate dari template — gratis, tetap M7.**

### Mode wa.me (pengganti API, tanpa biaya)

- Tabel baru: `wa_templates` (id, name, body dgn variabel {{nama}}, {{course}}, {{lesson}}, {{deadline}}, created_by, active) + `wa_link_log` (siapa membuka link untuk siapa, kapan — bukti niat, bukan bukti kirim).
- UI admin/guru: halaman CRUD template + live preview; tombol "Siswa mandek minggu ini" → daftar baris siswa + tombol 💬 wa.me (link = `https://wa.me/62xxx?text=` + encodeURIComponent(body terisi data siswa via Zod-validated nomor WA di profil).
- Inbound: tombol "Tanya ustaz" di halaman kursus → wa.me nomor guru, teks terisi identitas siswa dari sesi.
- Validasi: simpan nomor WA selalu format `62...` (strip `+`/`0` awal, regex `^62\d{8,14}$`); placeholder field `no_wa` di form pendaftaran Tally minta format ini.
- Batas yang diterima sadar: tidak ada delivery report, per-pesan butuh 1 klik manusia, bukan untuk blast massal (risiko blokir akun). Kalau kelak volume personal >±50 klik/minggu → baru tinjau ulang API (M7 lama tetap terdokumentasi di atas).

## Implementasi teknis WA (saat M7 nanti, jika jadi)

- Outbound via REST API (`Authorization: Bearer`, endpoint versi `/v23.0/<id>/messages`) — panggil dari Worker. Template harus sudah disetujui Meta → siapkan template sesuai trigger terpilih di atas.

## Risiko & catatan jujur

1. **10ms CPU Workers** — query D1 boros = sumber bug perf #1. Mitigasi: index FK, `SELECT` kolom spesifik, pagination server-side.
2. **Guru mengedit form Tally → field key berubah** → pipeline webhook rusak senyap. Mitigasi: alert needs_review (M6).
3. **Ketergantungan pihak ketiga**: Tally/GForm mengubah format embed → whitelist & normalizer terpusat di satu modul `embed.ts` supaya mudah ditambal.
4. **Biaya kirim.dev + Meta** bukan nol — satu-satunya kaki berbayar proyek. Batasi trigger WA sampai keputusan biaya user.
5. **URL `watch?v=` YouTube bisa di-embed, tapi kalau kelak butuh video privat → tidak ada jalur gratis yang benar. Putuskan lagi saat muncul.**
6. **OneDrive sebagai folder kerja**: file proyek (node_modules jutaan small files) bisa memberatkan sinkronisasi OneDrive. Mitigasi usulan: `node_modules` di-kecualikan dari sync (Settings → Choose folders / opsi exclude) — bahas sebelum M1.
7. **Satu Worker = satu blast radius**; deploy preview cukup `wrangler versions` kalau nanti perlu, belum di scope.
